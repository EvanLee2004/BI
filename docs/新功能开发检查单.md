# 新功能开发检查单（2.6.4）

每个改动批次开工前逐条答（写进 PR/任务书或 commit 说明）：

1. **需求口径谁定？** 陆总/业务方拍板还是工程自拟？
2. **数据够不够？** 缺表/缺列会怎样？覆盖率如何验？
3. **影响哪些既有口径？** 利润/费用/分摊/周期是否沾边？（沾边须停手写待拍板）
4. **动不动回归红线？** `regress_db_vs_files` 必须仍 32 周期零 diff
5. **手机端怎么办？** 390 视口是否破版？
6. **权限与 BU 隔离？** 他 BU 能否看见不该看的？
7. **失败了谁会知道？** 本机告警.log / 管理端横幅（禁止公司大群 webhook）
8. **非交互会不会卡死？**
9. **谁验收？** 明昊 / 业务方
10. **是否拍板结果？** 像疏漏的实现先 grep CHANGELOG/MADR/progress
11. **架构是否单源？** VM 类型、业务公式、API、样式 token 是否复用正本，还是复制出第二套？
12. **组件/模块职责是否清楚？** fetch、缓存、图表 option、大模板、业务计算是否挤在一个文件？
13. **图表是否诚实？** 金额比较是否共同尺度；0/缺失、实际/预测是否区分；关键值是否不靠鼠标也能读？
14. **测试是否真能防复发？** 故意恢复 bug 时是否必红，而不只是断言 DOM/源码字符串存在？
15. **发布是否真生效？** 是否证明 PID/启动时间和 runtime commit/build marker 已变化，而非只看 health 200？
