# MADR-0030 · 发布链半原子加固（3.7.0 · P1-02 + P1-03）

> 状态：Accepted · 2026-07-31  
> 范围：上机备份强制进链 + 成功门闸；**非**完整蓝绿/双机原子切换

## 背景

3.6.x 排查：P1-02 非原子发布、P1-03 备份未强制进发布脚本。生产为**单机** systemd + nginx 反代 `127.0.0.1:8018`，无独立候选主机。

## 决策

1. **强制备份（P1-03）**  
   标准发版入口 `deploy/linux/publish_kanban.sh` 在 `git pull`/`reload` **之前**调用 `db_backup.backup_sqlite`，落盘 `数据/备份/` + manifest（version/commit/sha256/关键表行数指纹）。无备份路径 → **非 0 退出，禁止继续**。

2. **成功门闸（P1-02 半原子）**  
   仅当同时满足才宣告成功：  
   - health HTTP 200  
   - runtime `metrics.version` == 磁盘 `VERSION`  
   - runtime `metrics.git_commit` 与磁盘 `HEAD` 可互包  
   - runtime `metrics.pid` 存在且与 reload 后 serve PID 一致（或由 `reload_verify.verify_process_switch` 判定进程已切换）  
   磁盘 VERSION 单独打印 **不算** 成功。

3. **预热 / 切换（尽力）**  
   - 本版：**尽力** = `reload_kanban.sh`（passwordless systemctl restart 优先，否则 kill + systemd Restart 拉起）+ 上列门闸。  
   - **未做**完整「旁路端口预热 → nginx 原子切换」：单机单端口、无第二 current 目录约定。  
   - 若未来要全原子：候选目录 + 备用端口 health + 符号链接/nginx upstream 切换，另开 MADR。

4. **失败与回滚**  
   - pull/reload 失败：保留备份 manifest；文档指引 `git reset --hard <prev>` + 必要时从 `数据/备份/*.db` 恢复（先停服）。  
   - 本脚本不自动改业务库。

## 与现有脚本关系

| 脚本 | 职责 |
|------|------|
| `db_backup.py` | SQLite backup API + manifest |
| `reload_verify.py` | 进程切换纯函数判据 |
| `reload_kanban.sh` | 停旧起新 + 轮询 health/runtime |
| **`publish_kanban.sh`（新）** | 备份 →（可选 pull）→ reload → 再校验 → 打印 SUCCESS/FAIL |

## 诚实标注

**半原子**：切换窗口内可能短暂断连；无双版本并行流量切换。相对 3.6.x 的改进是「无备份不上机」+「无 runtime 对齐不宣称成功」。

## 后果

- 发版 Runbook 以 `publish_kanban.sh` 为推荐入口  
- VERSION 记为 **3.7.0**（发布能力升级）  
- 不改利润口径 / CSRF / P0 安全面
